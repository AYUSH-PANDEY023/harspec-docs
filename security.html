Privacy and security

Everything stays local

harspec makes no network requests and has no telemetry. It reads your HAR file and writes files to your output folder.

Redaction

Redaction runs while the HAR is parsed, before inference or generation. A secret cannot reach the spec, an example or a client.

WhereWhat happens
Authorization headerScheme kept (Bearer), value replaced by <redacted>.
Cookie, Set-CookieCookie names kept, values redacted.
API key and CSRF headersValue redacted.
JSON, form and query fields named like password, token, secret, api_key, session, csrf, card, otp, jwtValue redacted.
Any string containing a JWTJWT replaced by <jwt>.

The test suite greps every output file for the secrets in the sample HAR and fails if any appear.

Important: Redaction is pattern based. Business data in example values (names, emails, IDs) is kept. Skim the output before you publish it anywhere.

Your HAR file is the sensitive part

  • Record on a test account when possible.
  • Do not email, upload or commit the .har. Add *.har to .gitignore.
  • Delete it when finished, and rotate any real credentials that were in it.

Use it responsibly

Only analyse traffic you are allowed to capture, and only call APIs you are allowed to use. Check the terms of service. harspec describes what a client already sends; it does not bypass authentication.

Report a vulnerability

Use GitHub private reporting (Security tab) on the repository. Do not open a public issue for security problems.
